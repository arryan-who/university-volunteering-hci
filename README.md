# HCI Project Research — University Volunteering Experience

## Overview

This project explores the **University Volunteering Experience** as a broken experience faced by students and committees.

The project follows a complete HCI process focused on **research, sensemaking, Information Architecture, and feature prioritization** rather than building a functional application.

## Phase 1 — Empathy & Definition

- Define the **Broken Experience** and problem space
- Create a **Proto-Persona** based on initial assumptions
- Conduct user interviews/observations
- Create a **True User Persona** from research
- Develop an **Empathy Map** — Say, Think, Do, Feel
- Create a **User Journey Map** and Emotion Line
- Identify the **Core Pain Point**
- Develop **User Stories** addressing the pain point

## Phase 2 — Ideate & Evaluate

- Identify **15–20 features/content items** from the User Stories
- Conduct an **Open/Hybrid Card Sort** with real users
- Analyze and document Card Sort patterns
- Create the **V1 Information Architecture (IA)**
- Conduct a **Tree Test**
- Identify where users failed
- Update the IA based on Tree Test findings

## Phase 3 — Prioritization

- Apply **MoSCoW Prioritization**
- Categorize features into:
  - Must-Have
  - Should-Have
  - Could-Have
  - Won't-Have
- Select a maximum of **4 Must-Have features**
- Evaluate the two most-debated features using a **DFV Matrix**
- Score the alternatives from **1–5**
- Select the final feature based on the DFV evaluation

## Deliverable

The final project is presented as a **single scrolling web page** built using:

- HTML
- CSS
- GitHub Pages

No JavaScript, Bootstrap, React, or other external frameworks are used.

## Project Focus

**Research → Empathy → Pain Point → User Stories → Features → Card Sort → IA → Tree Test → MoSCoW → DFV**

The objective is to demonstrate a **validated structural blueprint and prioritization strategy** for solving the identified broken experience.
